# 笔搭子 · AI 文学解读产品文档

> 版本：v1.0（对外面试版）｜ 数据截至 v12e（2026-08）｜ 状态：MVP 已上线，迭代中

---

## 0. 一页定位

> **「笔搭子」是一款面向个人创作者的极简在线写作 + AI 文学解读工具。** 用户写完一段文字，点击右下角悬浮球，AI 便以"文学导师"的方式给出：相似作家匹配、逐句原文批注、五维雷达评分、散文式总评、诗意升华句与续写启发，最后可一键生成带调性配色的分享卡片。

- **一句话价值主张**：无负担地写，像被懂文学的人读过一遍。
- **差异化**：不是通用聊天 AI，而是"读得懂中文文学语感"的写作陪伴——批注锚定原文、评价不挑硬伤而重共情、配色与续写呼应文风。

## 1. 背景与问题

### 1.1 用户问题
个人创作者（文学爱好者、日记写作者、灵感型创作者）在写作过程中普遍缺少即时、专业、有温度的反馈：
- 写完不知道自己的文字处于什么水平、像谁的风格；
- 找不到人逐句点评，或点评停留在"写得不错/继续加油"；
- 缺少能激发继续写作的"续写启发"。

### 1.2 市场缺口
通用大模型对话式 AI 能做分析，但：交互重（需要复制粘贴、描述需求）、反馈冷冰冰、没有创作场景下的"陪伴感"，也不产出可分享的美学结果。

### 1.3 为什么是现在
大模型 API 成本显著下降（本项目使用讯飞星辰免费 Qwen 模型），纯前端 + Serverless 即可支撑一个低成本可上线的单人产品，验证"AI 文学陪伴"这一细分场景。

## 2. 目标用户与核心场景

| 用户 | 画像 | 核心场景 | 关键诉求 |
|---|---|---|---|
| 文学爱好者 | 学生、青年，常写散文/随笔/诗歌 | 写完一篇想被"读懂"、想知道像谁 | 逐句批注、风格匹配、评语有温度 |
| 日记/随笔写作者 | 女性为主，情感表达型 | 记录心事，希望被看见、被回应 | 共情式反馈、不挑刺、鼓励性结尾 |
| 灵感型创作者 | 写作卡壳，需要启发 | 段落写到一半求续写 | 贴合文风的续写、一键采纳 |

## 3. 产品价值与核心体验

### 3.1 核心体验闭环
```
沉浸写作 → 点击悬浮球 → AI 解读（作家匹配 / 文内批注 / 五维评分 / 总评 / 升华句）
        → 续写启发（可一键采纳）→ 一键导出分享卡片
```

### 3.2 已实现的核心功能（v1–v12e）

| 模块 | 功能 | 设计要点 |
|---|---|---|
| 编辑器 | 极简无干扰写作，多篇分篇 Tab，localStorage 持久化，防抖自动保存 | 全宽移动端适配；滚动条瘦身 |
| 悬浮球 | 右下角固定入口，hover 放大 + "start reading"提示 | 生成中 loading，完成后返回编辑器视角 |
| AI 解读 | 相似作家匹配（液体球相似度百分比 + 保底外国作家）、文内逐句批注（整句锚定）、五维雷达评分（隐藏分值防虚高）、散文式总评（无小标题、不含祝福语）、诗意升华句独立呈现 | 同文同分（确定性评分）；名篇确定性识别（63 标志物 + 19 指纹，服务端优先）；内容未改复用上次解读 |
| 续写 | 300–500 字贴合文风的续写，以"淡色幽灵文本"呈现，滚过编辑器末尾揭示；一键采纳（回车）或忽略 | 单向触发，避免误触 |
| 调性视觉 | 文章调性自动分析 → 匹配低饱和色系，右栏/底栏/导出卡统一呼应文风；调性隐喻艺术字体（去括号） | ToneColorMap 五调 + default |
| 分享导出 | v12e 起改为**原生分享**（navigator.share 图片文件，不支持则下载），移除 jspdf；导出卡含：雷达图 + 分项分 + 金句 + 调性隐喻 | 移动端可直接分享到社交 App |
| 移动端 | 底部抽屉布局；编辑器高度自适应避让抽屉；3 段式滚动切换（底栏→右栏→续写→右栏） | 滚动事件与桌面严格隔离 |

### 3.3 关键交互决策（体现取舍）

1. **反馈语言从"挑硬伤"转向"共情解读"**：v3 起删除"找硬伤"，改为"意象对照 + 温暖评语"。理由：目标用户是情感型写作者，挑刺会摧毁写作意愿；共情更符合产品价值主张。
2. **祝福语 → 诗意升华句**：散文总评中禁止"祝你写作顺利"类套话，改为贴合文本的升华句独立呈现，避免廉价感。
3. **同文同分（确定性评分）**：同一段文字重复解读评分完全一致。理由：AI 波动会破坏用户信任，确定性是"工具感"的底线。
4. **名篇豁免/识别**：避免 AI 对经典名篇输出可笑点评；v12c 用服务端指纹优先于模型文风判断，把误判率降到最低。
5. **PDF → 原生分享**：真实使用中用户更倾向"分享"而非"下载文件"；原生分享让移动端分享链路短一倍。

## 4. 产品架构与技术方案

### 4.1 架构图
```
[React 18 + Vite 前端]
  ├─ Slate 编辑器（幽灵文本/批注锚定）
  ├─ Zustand（持久化 Store，localStorage）
  ├─ Framer Motion（动画）
  └─ html2canvas / qrcode（导出卡生成）

[API 层]
  ├─ Vercel Edge Function: /api/review（生产）
  ├─ 本地 dev-server.mjs: 3000 端口（开发，CORS 全开）
  └─ 讯飞星辰 MaaS 免费 Qwen 模型（xop35qwen2b）

[部署]
  ├─ Vercel 生产（bidazi.cloud / biedazi-react.vercel.app）
  └─ GitHub Pages（push main 自动构建部署）
```

### 4.2 关键设计
- **内容指纹缓存**：正文未改动时复用上次解读（reviewFp 指纹比对），省算力、响应快。
- **AI 输出可靠性**：重试 + 启发式兜底，应对截断/解析失败；服务端作家库白名单（不编造作家）。
- **前后端分离**：生产走 Vercel Edge，开发走本地 server，环境变量注入密钥。

### 4.3 数据模型（简化）
```
Article {
  id, title, author, content, createdAt, updatedAt,
  review: {
    author（相似作家）, annotations[]（原文批注+锚点）,
    scores（五维雷达）, summary（总评）, continuation（续写）,
    sublimation（升华句）, toneColor, thinkingSteps, generatedAt
  },
  reviewFp（内容指纹）
}
```

## 5. 成功指标

### 5.1 北极星指标
- **解读完成率**：发起解读后成功看到完整结果的比例（含"内容未改复用缓存"的秒回场景）。

### 5.2 核心指标
| 指标 | 说明 | 当前关注 |
|---|---|---|
| 解读请求成功率 | AI 链路可用性（Vercel Edge 跨地域调讯飞有间歇性失败，已定位为网络问题） | 需监控降级 |
| 续写采纳率 | 幽灵文本 → 一键采纳比例，衡量"续写启发"价值 | 高 |
| 分享导出率 | 每解读次数的导出分享次数，衡量传播价值 | 高 |
| 次周回访率 | 是否持续回来写作 | 中期 |

### 5.3 护栏指标
- 解读失败时不得出现空白面板或报错死屏（必须降级提示）。

## 6. 迭代复盘（v1 → v12e，产品思维展示）

迭代史本身就是一部"问题驱动"的产品复盘，贯穿五条主线：

| 主线 | 代表版本 | 解决的问题 |
|---|---|---|
| **布局遮挡** | v7 / v12b / v12d | 右栏、底栏、抽屉与编辑器争抢空间——用"布局状态机"思维逐次收敛（编辑器随面板出现立即左移；移动端编辑器压缩避让抽屉） |
| **AI 输出可靠性** | v3 / v5 / v12 / v12c | 截断→重试兜底；评分虚高→校准；评分波动→确定性评分；名篇误判→服务端指纹优先 |
| **文案调性** | v3 / v5 / v10 / v12 | 挑硬伤→共情解读；祝福语→诗意升华句；总评去小标题散文化 |
| **交互一致性** | v8 / v9 / v10 / v12b | 滚动/悬浮球/关闭的切换语义反复打磨（v10 悬浮球改为"返回编辑器"而非"关闭"，更符合直觉） |
| **移动端适配** | v3 / v12b / v12d | 底部抽屉、全宽编辑器、高度避让，Playwright 移动端回归验证 |

**沉淀出的产品原则**：
1. 反馈要有温度——目标用户为情感型写作者；
2. 工具要有确定性——评分、名篇识别必须可复现；
3. 分享要顺滑——分享是增长引擎，导出链路要最短；
4. 移动端是主战场——写作者常在手机碎片时间写作。

## 7. 竞品分析

| 竞品 | 形态 | 我们的差异 |
|---|---|---|
| 通用聊天 AI（ChatGPT/DeepSeek） | 对话式 | 我们零复制粘贴、场景内一键触发；结果可分享、有调性美学 |
| 写作软件内置 AI（如 WPS/飞书） | 办公向 | 我们不求润色公文，专注"文学语感"与陪伴感 |
| 批改/作文类 App | 应试向 | 我们面向自由创作，不评分考试，评语更私人化 |
| 社交写作平台（Lofter 等） | 社区向 | 我们提供即时私人反馈，无社交压力，先被 AI 读懂再决定是否公开 |

**护城河**：文学语感的 prompt/指纹工程 + 调性视觉体系 + 分享卡美学，三者叠加形成"懂文学的 AI 写作伴侣"心智。

## 9. 风险与未决决策

| 风险 | 等级 | 缓解 |
|---|---|---|
| Vercel Edge 跨地域调讯飞 MaaS 间歇性网络失败 | 中 | 已定位非代码问题；Next 迭代做重试+降级文案 |
| 大模型输出偶发幻觉（作家名/代表作不实） | 中 | 服务端作家白名单，只从库中选取，绝不编造 |
| 免费模型能力上限（解读深度/续写质量） | 中 | 后续可平滑切换付费模型，接口已抽象 |
| 单人维护，无自动回归 | 低 | 已有 Playwright 移动端验证 + Git 提交粒度（每版本一 commit） |

**未决决策（需产品负责人拍板）**：
1. 分享卡二维码落地目标：指定文章永久链接？（当前无后端持久化，仅 localStorage）
2. 是否全站统一"解读报告"品牌词（悬浮球 hover 文案等）。
3. 移动端 AI 偶发失败的可接受降级策略。
